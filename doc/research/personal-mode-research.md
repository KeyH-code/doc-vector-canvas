# Personal Mode 开发方案调研

日期：2026-11-20 · 状态：供评审，未定型、未实现

## 结论

**建议做一个以画布为主的轻量 Web 编辑器：借鉴 Excalidraw 的短操作路径、tldraw 的对象与历史操作边界、draw.io 对项目文件与导出物的区分。** 技术上优先验证 React + TypeScript + Vite + Fabric.js。用 Fabric.js 承接复杂的画布手势，项目自己负责对象数据、操作规则、历史和项目文件。不直接嵌入任何竞品的整套编辑器。

先做一条可独立演示的链路：**画矩形、输入中文 → 移动或缩放 → 保存项目文件 → 在新会话里重开并继续编辑**。同时验证不用鼠标、只通过内部命令也能修改这批对象。前者证明用户能用，后者证明未来 Agent 不必模拟点击，也不需要直接改渲染状态。

## 1. 证据与参赛范围

本次核对了[山软智库官方公告][contest]、本地[比赛规则](../../competition_rules.md)和[产品 README](../../README.md)。打开三个公开编辑器，用空白画布和临时矩形做了桌面浏览器操作抽查；未登录、未上传资料，未对竞品执行项目文件保存重开或实际下载验证。候选库以官方文档为依据，未安装依赖、未做本地集成原型。

| 优先级 | 建议范围 | 依据 |
| --- | --- | --- |
| 比赛基础功能 | 直线、矩形、椭圆、自由画笔；插入文本并改字体、字号、颜色；选中、缩放、旋转、复制粘贴；图形颜色与样式；本地保存和打开。 | 官方公告赛题 2「基础功能」。 |
| 项目应交付 | 移动对象；撤销/重做；导出选中对象为 SVG；空白画布独立可用，不依赖账号、后端或 Agent。 | 移动、撤销/重做、SVG 来自项目目标；无账号/后端是本轮交付建议，不是题面要求。 |

| 延后 | 图层面板、吸附对齐、PNG 导出、复杂图形库、连接点绑定、实时协作、富文本。PDF/PPTX 导入和真实 Agent 也不进入 Personal Mode。 | 图层等为公告进阶举例，不必全做；避免拖延基础闭环。 |

## 2. 成熟产品观察

| 产品 | 网页实测 | 官方文档补充 | 借鉴与取舍 |
| --- | --- | --- | --- |
| [Excalidraw][excal-app] | 顶部并排摆放选择、矩形、椭圆、箭头、直线、自由笔和文字。用矩形工具拖出图形后回到选择工具，侧边出现描边、背景、线宽和透明度等设置；实际点击撤销、重做，按钮状态随之切换。菜单分别提供打开、保存到、导出图片；导出弹窗显示 PNG/SVG。 | [官方上手指南][excal-start]说明快捷键，[格式文档][excal-json]说明可重开文件是 JSON。 | 采用同一排工具入口、完成常规绘制即回到选择、上下文样式面板；外观用规整线条和清晰汉字，不照搬手绘风或品牌 UI。 |
| [tldraw][tl-app] | 底部工具栏、右侧颜色和填充等样式入口、左下撤销/重做。画矩形后选中对象；执行复制（Duplicate）、撤销、重做，画布对象数量为 `1 → 2 → 1 → 2`。这不是对系统剪贴板的验证。 | [Editor API][tl-editor]与 [Store][tl-store]把选择、对象、快照、事务和历史分开。 | 借鉴「按对象 ID 改图」「一次动作一次撤销」，以及工具当下有明确状态；不把现行 SDK 作为首选交付依赖。 |
| [draw.io][draw-app] | 设备模式下，点工具栏「矩形」即可插入；右侧切为「样式 / 文本 / 排列」，打开「排列」看到大小、位置、旋转；顶栏提示修改未保存。左侧有大量形状类别。 | [图形文档][draw-shapes]说明选择、拖拽缩放和旋转控制点；[保存][draw-save]与 [SVG 导出][draw-svg]各有独立入口，后者可仅导出选中对象。 | 采用清楚的文件操作和选中后可见的属性。暂不做形状库、模板库、复杂布局面板，也不复刻三层格式选项。 |

## 3. 推荐的界面与交互

```text
┌ 文件：新建 · 打开 · 保存项目                      未保存提示 · 导出选中 SVG ┐
├ 工具：选择 · 抓手 · 直线 · 箭头 · 矩形 · 椭圆 · 画笔 · 文字                ┤
│                                                              ┌ 属性 ┐ │
│                 大面积干净画布                                 │ 描边 │ │
│                 选中时显示边框、缩放和旋转手柄                  │ 填充 │ │
│                                                              │ …    │ │
│  撤销 · 重做                                     缩小 · 100% · 放大   │
└───────────────────────────────────────────────────────────────────────┘
```

这是布局草案，不是实现截图。推荐浅色中性背景、规则实线、少量高对比选中强调色。默认不显示复杂网格；选择框、控制点和原始图形要能明显区分。画布缩放只改变观看大小，**不改变物体自身尺寸**。

| 操作 | 建议行为 |
| --- | --- |
| 绘制 | 切工具后按住拖拽，过程显示预览，松手提交一次；微小误触不创建图形。基础图形完成后切回选择并选中新对象。画笔可连续画，每笔生成一个独立可移动对象。 |
| 文字 | 选择文字工具后点击输入，双击已有文字继续编辑；支持字号、颜色和有限的字体选项。手测中文输入法、换行与光标；候选词未提交时，回车、Esc 或字母快捷键不能误触画布操作。 |
| 选择与变换 | 点击选中，空白处拖动框选，Shift 追加选择；拖动本体移动，角点缩放，独立手柄旋转。建议先验收单对象缩放和旋转，再做多选的复杂变换；多选复制、移动和选区导出仍需验证。直线、箭头和笔迹要有合理的点选容差。 |
| 属性 | 选中图形显示描边颜色、线宽、线型；封闭图形再显示填充。文字仅显示相关属性，不让无效设置生效。画布上的编辑控件不进入导出文件。 |
| 复制与历史 | 支持应用内 Ctrl+C / Ctrl+V，副本获得新 ID、略微偏移、自动选中；不承诺跨应用复制矢量。拖动再久也只撤销一次；选中、平移、缩放画布不进入文档历史。编辑文本时，复制、删除和撤销优先交给文本控件。 |
| 文件 | 「保存项目」生成可重开文件，「导出选中 SVG」生成可插入其他工具的图；无选区时禁用后者。打开新文件前保护未保存改动，失败或取消时保留当前画布。首版不把浏览器缓存当成唯一存档。 |

## 4. 技术候选与建议

| 路线 | 现实收益 | 关键代价或风险 | 结论 |
| --- | --- | --- | --- |
| **Fabric.js + 自有界面** | [官方核心概念][fabric-core]与[画笔演示][fabric-draw]覆盖交互对象、选择/变换、画笔和 SVG 输出，项目源码为 [MIT][fabric-license]；可以自定界面。 | 手动拖拽和文字编辑会直接改 Fabric 临时对象，要把结果正确收敛为项目命令。选区 SVG 裁切、中文字形和后续背景叠加不是开箱即验收。 | **首验**。已有手势可省下手写控制点、击中检测与输入处理的一部分工作，同时保留产品边界。 |
| Excalidraw SDK | 成熟编辑体验；[SDK][excal-api]公开读取图元、`updateScene`、`captureUpdate`，[导出文档][excal-svg]提供 SVG 工具；代码 [MIT][excal-license]。 | 已有界面、状态与历史归 SDK。页面背景、与 PDF 共用视口、按 ID 局部修改、单轮撤销和字体要求要另测。 | 若工期优先且 SDK 通过同一组验收，可作为快速备选；不默认拿它改皮交付。 |
| React + 原生 SVG | [SVG `viewBox` 与 `transform`][svg-viewbox]可直接表达视口和几何；所见图元更容易映射到导出，减少对编辑器运行时的耦合。 | 框选、旋转缩放、变换手柄、画笔、文本输入覆盖层和命中容差都要自己做。 | Fabric 不能稳定闭合数据与编辑操作时再试；不能只因“本来就是 SVG”低估编辑器工作量。 |
| tldraw SDK | 存在明确的对象 ID、选区、事务、快照、撤销 API。 | [现行 SDK 许可说明][tl-license]明确生产环境需要有效密钥；非商业 Hobby 授权需申请并保留水印。不能把网页免费体验当成 SDK 的交付许可。 | 借鉴设计，暂不作为依赖。 |

**应用形态建议：** Personal Mode 做纯前端，优先保证 Windows 桌面 Chrome/Edge 有可复现启动路径。[Vite][vite-guide]负责开发与构建，React 管工具条、文件菜单和属性面板，TypeScript 定义可序列化数据与操作。保存用下载，打开用浏览器标准[文件选择][file-api]；无需为“保存到同一路径”先选择专用文件权限方案。版本、浏览器范围和安装方式由计划结合实际环境确认。实际采用的库、字体、图标及素材单独核对许可证并记录，竞品链接只是参考来源，不代表引入其代码或素材。

## 5. 为 Agent 留下的边界

**一份正式对象数据，两种操作来源。** 把 Fabric 当成桌面上的图纸，而不是账本：界面可以实时预览，但可保存、撤销和验证的正式记录在项目画布模型里。下面是设计约束，不是已定 API 签名。

| 边界 | Personal Mode 要落实什么 | Agent Mode 如何复用 |
| --- | --- | --- |
| 画布模型 | 对象有稳定 ID、类型、几何、样式和绘制顺序，归属于一个画布空间。保存重开保留 ID；复制创建新 ID。项目文件有格式版本；工具、鼠标位置、选区、视口不是对象数据。 | 用「空间 ID + 对象 ID」精准改图；将来一个空间可对应一页文档的标注层或独立示意图。文档引用、页码、选区快照由 Agent Mode 增加，不假装现有文件已支持 PDF/PPTX。 |
| 坐标和图层 | 对象保存世界/空间坐标，不保存鼠标屏幕像素。平移缩放和高 DPI 只参与显示映射。背景与对象分离，选择框和手柄仅用于交互。 | 未来每个文档页用固定页内坐标；底图锁定，不是可被改写的图元。原文圈选区域和可编辑对象的 ID 列表是两种不同上下文。PDF 的原点和旋转转换留在渲染适配层，见 [PDF.js 示例][pdf-examples]。 |
| 操作入口 | 提供读取选中 ID、按 ID 读取图元；写操作至少表达创建、更新属性/内容/几何、复制和删除。鼠标按住时先预览，松手从 Fabric 事件提取最终结果，通过同一入口提交。选区、视口、保存等不必全部暴露给 Agent。 | 后续工具适配器把请求转换成这些命令，不传 Fabric 实例、不模拟鼠标、不允许直接替换整个场景。 |
| 历史与刷新 | 一次手势或批次只产生一个撤销步。先验证整批，失败不写入一半；提交成功后统一刷新画布。同步时防止「命令更新 Fabric → Fabric 事件再次提交」的回环。 | 用户请求发起时冻结指定空间和目标权限；改选中对象时只放行快照中的 ID，过期或越界则拒绝。首版可先整轮提交一次，实时预览等真实工具链跑通再决定。 |
| 持久化与出图 | 版本化 JSON 保存业务图元，不把 Fabric 实例或运行时 JSON 当成长期项目契约；只认可支持的类型和字段，校验成功后才替换当前项目。SVG 从指定对象集导出，不包含选框、视口镜头、背景页或其他未选图形。 | 模型可读的数据、可撤销的编辑和用户可携带的文件使用同一份正式状态。PDF/PPTX 文件是否内嵌或引用仍待决策。 |

**无模型验收例：** 画布先有 A、B、C。用内部命令只改 A 的文字和 B 的位置，C 保持不变，一次撤销恢复 A/B。再用「改 A + 改不存在的 ID」提交一批，确认 A 不发生半次修改、历史不增加。此验收不需要连接 Agent，目的是尽早发现画布操作边界是否可用。

## 6. 交给下一阶段验证的决策

先做限时技术验证，再锁定开发方案。若候选库仅能“画出矩形”，不能证明下面的边界，不应直接进入全量编辑器实现。

| 验证项 | 最小通过证据 |
| --- | --- |
| 手工编辑与命令一致 | 同一个矩形既能拖动又能按 ID 改色；拖动只记一次历史，程序修改没有重复写入。有效批次可一次撤销，混入无效 ID 的批次不产生部分改动。 |
| 中文文字和坐标 | 用 Windows 中文输入法录入 `帧数增加 & 预算不变`，字号、字体、文字改动均可保存。对同一张模拟底图，在 50%/100%/200% 缩放和平移下编辑或重开时，图元与底图标记对齐；改变设备像素比不应改变存档几何。 |
| 项目文件往返 | 下载后在另一浏览器会话打开，比较对象 ID、几何、层叠顺序、文本和样式；仍能继续编辑。旧或未知格式、损坏文件给予明确提示，当前未保存画布不丢失。首版无需实现旧版迁移，但要明确拒绝不支持的版本。 |
| 选区 SVG | 选中文字、旋转后的矩形、线或箭头出图；SVG 在浏览器和目标 PPT 中看得见、无裁切、不夹带未选图元。额外验证中文字体回退、`&` 等文本转义、宽描边和箭头端点是否被裁掉；不要依赖 `foreignObject` 或运行时 CSS 才显示核心内容。 |

**后续计划建议按交付物拆分：** ① 验证候选引擎和数据边界；② 完成「矩形 + 中文文字 + 编辑 + 本地保存重开」；③ 补齐题面工具、对象操作、撤销重做与 SVG；④ 验收无模型命令、浏览器复现和参赛材料。以上是调研产出的顺序建议，不是开发计划；用户确认优先项后再写入 `doc/plans/`。技术验证不通过时，优先判断是 Fabric 适配问题还是 Web 编辑方案不适合，再拿备选跑同样的最小用例。
